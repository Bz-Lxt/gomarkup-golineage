# GoLineage 设计规范（DesignSpec）

> 版本：v1.0 ｜ 阶段：PHASE 2 ｜ 时区：GMT+8

---

## 1. 设计定位

### 1.1 使用场景与用户

| 维度 | 描述 |
|---|---|
| 用户 | 运维/SRE、数据治理工程师、金融风控分析师 |
| 环境 | 办公室大屏或双显示器，长时间凝视，常在夜间值班场景使用 |
| 核心动作 | 找到一个资产 → 看清它连着谁 → 判断改动会炸到哪里 → 回溯它何时变成这样 |
| 情绪目标 | 可信、克制、专注。用户在排障时不需要「愉悦」，需要**一眼看懂** |

### 1.2 美学方向：深空控制台（Deep Space Ops Console）

选定**暗色工业控制台**方向，理由并非跟风：

1. **图可视化的物理需求**。节点需要 8 种以上可区分的类型色。高饱和色在浅底上会互相打架并刺眼，在深底上则各自清晰、互不干扰。这是 Neo4j Browser、Datadog、Grafana 一致选择暗色的根本原因。
2. **值班场景**。凌晨排障时浅色大面积白底是生理负担。
3. **信息层级**。深底让「发光」成为可用的强调手段——高亮路径、脉冲节点、风险描边，都能靠亮度而非仅靠色相区分。

**记忆点**：整个界面像一台仪器而不是一个网站——切角面板、扫描线、等宽数字、坐标网格背景。用户关掉页面后会记得「那个像雷达站的血缘图」。

### 1.3 反面清单（明确不做）

- 不用紫色渐变 + 白底的通用 AI 审美
- 不用 Inter / Roboto / Arial / 系统默认无衬线
- 不用圆润卡片 + 大圆角 + 柔和阴影的 SaaS 模板感
- 不用 Element Plus / AntD 默认皮肤（工程师 UI，且深色定制成本高于自研）
- 不用原生 `alert` / `confirm` / `prompt`
- 不用浏览器原生 `<select>` 箭头

## 2. 色彩系统

### 2.1 骨架色（Chrome）

全部以 CSS 变量定义于 `src/styles/main.css` 的 `@theme` 块中。

| 变量 | 色值 | 用途 |
|---|---|---|
| `--color-void` | `#07090E` | 页面最底层，画布背景 |
| `--color-panel` | `#0E121A` | 侧栏、抽屉、工具条底色 |
| `--color-elevated` | `#151A24` | 卡片、输入框、悬浮项 |
| `--color-line` | `#222A38` | 常规 1px 分隔线与边框 |
| `--color-line-strong` | `#2E3A4D` | 聚焦态边框、面板切角 |
| `--color-ink` | `#E6EAF2` | 主文本 |
| `--color-ink-dim` | `#8B95A8` | 次级文本、标签 |
| `--color-ink-mute` | `#5A6577` | 占位符、禁用态 |

### 2.2 语义色

| 变量 | 色值 | 语义 |
|---|---|---|
| `--color-signal` | `#2DD4BF` | 主交互色：选中、聚焦、确认。信号青 |
| `--color-amber` | `#F5A524` | 路径高亮、中风险告警 |
| `--color-danger` | `#F2555A` | 删除、高风险、错误 |
| `--color-violet` | `#A78BFA` | 时间轴/历史态的专属色，与「当前态」形成区分 |

**时间轴用紫是刻意的**：当用户拖动时间轴进入历史模式时，整个画布的强调色从青切到紫，从颜色上就无法把「历史快照」误认成「当前拓扑」。这是防误操作设计，不是装饰。

### 2.3 节点类型色板

采用 AntV 经典 10 色板中在深底上明度达标的 8 色。每种资产类型固定一色，全局不变（图例、列表、抽屉、事件流均复用），保证用户建立肌肉记忆。

| 类型 | 中文 | 色值 |
|---|---|---|
| `server` | 服务器 | `#5B8FF9` |
| `database` | 数据库 | `#5AD8A6` |
| `application` | 应用 | `#F6BD16` |
| `api` | 接口 | `#E8684A` |
| `person` | 人员 | `#6DC8EC` |
| `account` | 账户 | `#9270CA` |
| `middleware` | 中间件 | `#FF9D4D` |
| `storage` | 存储 | `#269A99` |

### 2.4 风险等级色

`risk_level` 属性是业务硬需求（用户明确要求可为节点添加「风险等级」），因此给予独立视觉编码：节点外描边。

| 值 | 描边色 | 视觉 |
|---|---|---|
| `critical` | `#F2555A` | 3px 红环 + 呼吸动画 |
| `high` | `#F5A524` | 3px 琥珀环 |
| `medium` | `#F6BD16` | 2px 金环 |
| `low` / 缺省 | 无 | 仅类型色填充 |

## 3. 字体系统

三套字体各司其职，全部通过 `@fontsource` **本地打包**，不依赖 CDN——离线部署与国内网络下 Google Fonts 不可达是真实风险。

| 角色 | 字体 | 字重 | 用途 |
|---|---|---|---|
| 显示 | **Chakra Petch** | 500 / 600 | 产品名、面板标题、按钮。方形切角带 HUD 气质，与控制台方向一致 |
| 正文 | **IBM Plex Sans** | 400 / 500 | 说明文字、表单标签。IBM 为技术文档设计，中性但不寡淡 |
| 数据 | **IBM Plex Mono** | 400 / 500 | 所有 ID、时间戳、数值、属性键。等宽保证纵向对齐 |

**中文**：不打包中文 webfont（Noto Sans SC 全量近 10MB，会让首屏与镜像体积失控）。中文走系统栈回退：

```
"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Source Han Sans SC", sans-serif
```

拉丁字符走打包字体、中文走系统字体的混排，在中文技术产品里是标准做法，视觉上也协调。

**数字**：全站 `font-variant-numeric: tabular-nums`，避免数字跳动。

## 4. 空间与形态

| 项 | 规则 |
|---|---|
| 基础栅格 | 4px。所有间距为 4 的倍数 |
| 圆角 | 2px（输入/按钮）、4px（面板）。**刻意保持锐利**，圆角越大越像消费级 SaaS |
| 边框 | 恒定 1px。层级靠颜色区分，不靠粗细 |
| 阴影 | 深色下阴影几乎不可见，改用**发光**表达层级：`box-shadow: 0 0 0 1px var(--color-signal), 0 0 24px -8px var(--color-signal)` |
| 面板切角 | 主面板左上/右下用伪元素画 L 形角标（8px），仪器感的来源 |

### 4.1 布局骨架

```
┌──────────────────────────────────────────────────────────┐
│ TopBar  产品标识 │ 场景搜索 │ 布局切换 │ 统计徽章 │ 连接态  │ 48px
├────────┬─────────────────────────────────────┬───────────┤
│ 左栏   │                                     │ 右抽屉    │
│ 240px  │        G6 画布（flex-1）             │ 360px     │
│        │                                     │ 按需出现  │
│ 搜索   │   · 节点拖拽 / 缩放 / 框选           │ 属性编辑  │
│ 类型   │   · 点击高亮邻居                     │ 血缘面板  │
│ 图例   │   · 最短路径高亮                     │ 事件流    │
│ 分析   │                                     │           │
├────────┴─────────────────────────────────────┴───────────┤
│ TimelineBar  时间轴回溯（历史模式下整体转紫）              │ 88px
└──────────────────────────────────────────────────────────┘
```

**响应式**（知识库要求覆盖 768 / 480 两级断点）：

- `≥1280px`：三栏并存
- `768–1279px`：左栏折叠为图标条（40px），点击浮出
- `<768px`：左栏抽屉化，右抽屉全宽，时间轴压缩为 64px 且隐藏刻度标签
- 页面级容器一律 `w-full`，不设 `max-w-*`

## 5. 动效

克制原则：动效服务于**理解状态变化**，不做无意义装饰。

| 场景 | 效果 | 时长 |
|---|---|---|
| 页面首载 | 面板从 `translateY(8px) opacity:0` 错峰进入（stagger 60ms） | 400ms |
| 节点选中 | 同心圆脉冲扩散一次 + 邻居节点亮起、非邻居降至 15% 透明度 | 300ms |
| 路径高亮 | 路径边沿方向流光（`stroke-dashoffset` 循环） | 1.2s loop |
| 高风险节点 | 红环呼吸（opacity 0.4↔1） | 2s loop |
| 时间轴拖动 | 画布顶部掠过一道扫描线，强调色切紫 | 600ms |
| 抽屉进出 | 右侧滑入 + 背景轻微模糊 | 240ms `cubic-bezier(.32,.72,0,1)` |
| Toast | 顶部滑落，5s 自动消失，可手动关闭 | 200ms |

全部动效遵循 `prefers-reduced-motion` 降级为瞬时切换。

## 6. 组件清单（全部自研）

不引入组件库，以保证深色控制台风格的一致性。

| 组件 | 职责 | 关键约束 |
|---|---|---|
| `AppButton` | 按钮 | 变体 primary/ghost/danger；禁用态明确；无「死按钮」 |
| `AppSelect` | 下拉 | **禁用原生箭头**，自绘 12×8 折线 SVG，`padding-right: 36px` |
| `AppInput` | 输入 | 聚焦发光；错误态在下方渲染红色提示文本 |
| `AppDrawer` | 右抽屉 | ESC 关闭、遮罩点击关闭、焦点陷阱 |
| `AppModal` | 确认框 | 替代原生 confirm，危险操作必经 |
| `AppToast` | 消息 | 支持手动 × 与 5s 自动消失 |
| `AppTag` | 标签 | 类型色 / 风险色两种语义 |
| `AppSlider` | 时间轴滑块 | 键盘 ←→ 可调，拖动时显示时刻气泡 |
| `AppSpinner` | 加载 | 旋转扫描弧，非通用圆环 |

## 7. 交互契约（对应用户明确需求）

| 需求原文 | 实现 |
|---|---|
| 节点拖拽 | G6 `drag-element` behavior |
| 放大缩小 | G6 `zoom-canvas` + 工具条按钮 + 双击聚焦 |
| 点击高亮相邻节点 | 单击 → 一跳邻居保持原色，其余元素透明度降至 15% |
| 高亮最短路径 | 选起点与终点 → 调 `/graph/shortest-path` → 路径边琥珀色 + 流光动画，路径外元素淡出 |
| 动态节点属性编辑 | 右抽屉键值编辑器，支持增/删/改；键名前端与后端双重正则校验；值类型自动推断（数字/布尔/字符串） |
| 时间轴回溯 | 底部滑块映射 `earliest ~ latest`，拖动调 `/timeline/snapshot?at=`，画布重绘为历史拓扑并转紫；提供「Diff 当前」查看增删改 |

### 7.1 表单校验（遵循知识库硬性要求）

属性编辑器不是「标个星号就算数」：

- 保存前调用统一 `validateProperties()`
- 键名正则 `^[\p{L}\p{N}_-]{1,64}$`，与后端 `service` 层规则一致
- 键名重复、空值 → 字段下方红色提示 + 拦截保存
- 权重字段有上下界（0.01–1000），从 schema 读取而非硬编码
- 校验失败时同时弹 Toast 汇总

## 8. 日期格式

遵循知识库规则：**用户可见的一切时间统一 `yyyy-MM-dd HH:mm:ss`**，内部传输保持 ISO 8601（RFC3339 + `+08:00`）。

时间参数拼入 URL 时**必须** `encodeURIComponent` —— `+08:00` 的加号若未编码会被服务端解码为空格。（后端已做容错兜底，但前端不应依赖兜底。）

## 9. 可访问性

- 所有交互元素可 Tab 聚焦，聚焦环使用 `--color-signal` 且对比度 ≥ 3:1
- 正文对比度 `#E6EAF2` on `#0E121A` ≈ 13.8:1，远超 WCAG AA
- 次级文本 `#8B95A8` on `#0E121A` ≈ 6.2:1，达 AA
- 图例不仅用颜色区分，同时附类型名文本
- 抽屉、弹窗具备 `role` 与 `aria-*`，ESC 可关闭
